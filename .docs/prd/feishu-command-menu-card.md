# PRD: Feishu Command Menu Card

## Problem Statement

The owner can operate the Personal Bridge from a Feishu private Chat, but many supported capabilities require remembering slash commands and their arguments.

This is especially awkward for Workspace and Agent Session workflows. Commands such as `/ws use <name>` and `/resume <session_id>` require the owner to know or copy exact identifiers. The bot already has the underlying behavior, but the private Chat experience does not expose that behavior as a discoverable control surface.

The owner wants a Feishu bot menu entry that opens a deterministic command panel. The panel should provide shortcut buttons and second-level selection cards without starting an Agent Turn or calling an LLM.

## Solution

Add a Feishu Adapter command menu flow.

When the Feishu backend custom bot menu sends the exact event key `aw_bot_menu()`, the bot sends a command menu card to the Private Chat Scope. The card presents common owner actions such as starting a fresh Agent Session, stopping the active Run, opening Workspace selection, opening historical Agent Session selection, and configuring Idle Timeout.

Simple actions execute by mapping card button actions to existing text commands. Actions that need parameters open second-level cards. For example, Workspace selection opens a card listing saved Workspaces, and choosing a Workspace maps to `/ws use <name>`.

All menu responses are generated by deterministic code. The menu event and menu card actions do not call Codex, OpenCode, or any LLM. Only ordinary owner task text starts an Agent Turn.

## User Stories

1. As the owner, I want to click the Feishu bot menu item, so that I can see available bridge commands without remembering slash commands.
2. As the owner, I want the menu event to return a command panel without starting a Run, so that opening the menu is safe during active work.
3. As the owner, I want one-click access to `/stop`, so that I can interrupt an active Run quickly.
4. As the owner, I want one-click access to `/new`, so that I can start with a fresh Agent Session in the current Workspace.
5. As the owner, I want one-click access to `/reset`, so that I can clear the current Agent Session explicitly.
6. As the owner, I want to open a Workspace panel, so that I can choose a saved Workspace from a list instead of typing its name.
7. As the owner, I want each saved Workspace to show its name, path, and update time, so that I can choose the right local directory.
8. As the owner, I want to click a saved Workspace's use button, so that the bot switches Workspace through the same behavior as `/ws use <name>`.
9. As the owner, I want an empty Workspace list state, so that I understand there are no saved Workspaces yet.
10. As the owner, I want to open a historical Agent Session panel, so that I can resume compatible context without copying a session id manually.
11. As the owner, I want historical Agent Sessions to show useful identifying details, so that I can tell sessions apart before resuming one.
12. As the owner, I want a resume button for each compatible historical Agent Session, so that the bot restores that Agent Session through the same behavior as `/resume <session_id>`.
13. As the owner, I want an empty historical Agent Session state, so that I know there are no compatible sessions for the current Agent, Workspace, and Access Mode.
14. As the owner, I want an Idle Timeout panel, so that I can choose common timeout settings without remembering `/timeout` arguments.
15. As the owner, I want timeout buttons for fixed values, off, and default, so that I can quickly adjust the watchdog behavior.
16. As the owner, I want a help panel, so that I can see the supported text commands and what the menu buttons do.
17. As the owner, I want the menu to work while a Run is active, so that I can stop or inspect options without changing Run state accidentally.
18. As the owner, I want menu card actions to stay separate from approval buttons, so that approving an Agent Pending Request cannot be confused with opening a menu panel.
19. As the owner, I want menu actions to preserve existing command semantics, so that `/new`, `/reset`, `/ws use`, `/resume`, and `/timeout` behave the same from text or cards.
20. As a maintainer, I want the menu feature to stay inside Feishu Adapter code, so that Bridge Core remains provider-neutral.
21. As a maintainer, I want menu tests to use fakes and local data, so that tests never call real Feishu, Codex, OpenCode, or LLM services.

## Implementation Decisions

- The Feishu backend custom bot menu event key is the exact string `aw_bot_menu()`.
- The exact event key must be matched as configured, including parentheses.
- The menu event is a Feishu Adapter input shape, not a Bridge Core concept.
- The menu event sends a command menu card and does not call Bridge Core command handling.
- The menu event does not start an Agent Turn.
- The menu event does not call Codex, OpenCode, or any LLM.
- Runtime assembly should wire a menu event callback alongside message and card action callbacks.
- The Feishu Gateway should normalize the backend menu callback into an internal incoming menu event that includes Chat and User identity.
- The Feishu Private Chat Adapter should handle incoming menu events by sending menu cards.
- Menu card actions should use a `menu:` command prefix to avoid colliding with existing Run View actions such as stop, approve, and reject.
- Existing Run View actions should remain unchanged.
- Direct menu actions should map to existing text commands through the same Core use case used by private Chat text.
- Parameterized actions should first render a second-level card, then map the selected value to an existing text command.
- Workspace listing should use existing persistence behavior for saved Workspaces.
- Workspace use should map to `/ws use <name>`.
- Workspace deletion is deferred for the first version unless a confirmation card is added.
- Current Workspace path input through `/cd <path>` is deferred for the first version unless card input components are added.
- Saving the current Workspace through `/ws save <name>` is deferred for the first version unless card input components are added.
- Historical Agent Session listing should reuse the existing compatibility rules used by `/resume`.
- Historical Agent Session restoration should map to `/resume <session_id>`.
- Idle Timeout buttons should map to `/timeout 5`, `/timeout 10`, `/timeout 30`, `/timeout off`, and `/timeout default`.
- The help panel should be static and deterministic.
- Opening the menu must not affect an active Run.
- Menu actions that map to existing commands should preserve the existing active Run behavior for those commands.
- If a Pending Request is open, menu card actions should still be handled as card actions, not as user-input answers.
- No new Bridge Core glossary term is needed for the menu.
- No ADR is needed for this feature because the decision is localized to Feishu Adapter behavior and is reversible.

## Testing Decisions

Good tests should prove that the menu is deterministic Adapter behavior and that it preserves existing command semantics.

Highest practical test seams:

- Feishu Gateway menu event normalization.
- Runtime assembly wiring for the menu event callback.
- Feishu Private Chat Adapter handling of the exact `aw_bot_menu()` event key.
- Menu card rendering for the first-level command panel.
- Menu card action parsing for `menu:` actions.
- Direct command mapping from card actions to existing text commands.
- Workspace panel rendering with several saved Workspaces.
- Workspace empty state rendering.
- Workspace use action mapping to `/ws use <name>`.
- Historical Agent Session panel rendering with compatible sessions.
- Historical Agent Session empty state rendering.
- Historical Agent Session restore action mapping to `/resume <session_id>`.
- Idle Timeout panel action mapping.
- Help panel rendering.
- Regression coverage that stop, approve, and reject Run View actions still work.

Prior art exists in the current Feishu Gateway, Feishu Private Chat Adapter, Run View Sink, renderers, Core Workspace command, Core Resume, and Core Idle Timeout tests.

Tests must use fakes or mocks. They must not call real Feishu, Codex, OpenCode, LLM clients, or provider APIs.

## Out of Scope

- Dynamically configuring Feishu backend custom bot menu entries through SDK or OpenAPI.
- Group menu APIs.
- Group Chat workflows.
- Starting Agent Turns from the menu event itself.
- Calling an LLM to generate menu content.
- Filling the Feishu Chat input box without sending.
- Attachment intake.
- `/cd <path>` card form in the first version.
- `/ws save <name>` card form in the first version.
- `/ws remove <name>` without a confirmation flow.
- Rich multi-step form state beyond simple second-level cards.
- Changing Bridge Core vocabulary.
- Adding new Agent capabilities.

## Further Notes

This feature extends the Personal Bridge's private Chat usability without changing the provider-neutral Bridge Core.

The menu is a Feishu UI control surface over existing behavior. It should stay thin, deterministic, and easy to test.
